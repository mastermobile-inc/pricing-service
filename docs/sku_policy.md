# Положение о присвоении Артикула (SKU)

Версия: 1.2
Обновлено: 2026-09-14
Применимо: все товары (аккумуляторы, дисплеи, кабели, зарядные устройства, запчасти и т.д.)  
Контур: 1С (УТ 10.3/11), инвойсы, пэкинг-листы, этикетки, маркетплейсы

## 1. Цель и зона действия

- Обеспечить единые правила кодирования Артикула (SKU) без доработок 1С и без создания новых реквизитов.
- Артикул служит единственным коммерческим кодом (он же SKU) во всех внешних документах и на маркировке.
- Для действующих товаров исторические числовые Артикулы не изменяются. Новые товары кодируются по правилам ниже.

## 2. Формат SKU (универсальная схема)

`<BR>-<CAT>-<DEV>-<KEY>-<REV?>`

Где:

- `BR` – префикс бренда/линейки:
  - `F5` — F5ENERGY,
  - `OFN` — Offonika,
  - `OEM` — безбренд/прочее.
- `CAT` – категория товара (см. §3).
- `DEV` – устройство/платформа (модель телефона и т.п.): `IPH11`, `IPH12MN`, `SMG-A50`, `XMI-RED9`, `HWE-P40` и т.д.
- `KEY` – ключевой параметр категории.
- `REV` – ревизия/вариант. Необязательный суффикс, использовать только при необходимости различать близнецов или коммерчески разные варианты одной и той же позиции.

Требования к записи:

- только латиница и цифры;
- разделитель `-`;
- без пробелов;
- длина до 35 символов.

Примеры:

- Аккумулятор: `F5-BAT-IPH11-3470`
- Дисплей: `F5-DSP-IPH11-INCELL-BLK`
- Кабель: `F5-CBL-USBC-LTN-1M-WH`
- Зарядка: `F5-CHR-65W-GAN-EU`

## 3. Справочник категорий (CAT) и поле KEY

| CAT | Категория | KEY — правило кодирования | Примеры KEY |
| --- | --- | --- | --- |
| `BAT` | Аккумуляторы | Основной вариант: `mAh`; для повышенной ёмкости: `HCxxxx`; допустимый fallback: код аккумулятора (`battery_code`), если ёмкость отсутствует, не подтверждена или неоднозначна | `3470`, `HC3470`, `A1527`, `EB-BS901ABY` |
| `DSP` | Дисплеи (модули) | тип + цвет (+ грейд) | `INCELL-BLK`, `OLED-BLK-AAA` |
| `GLS` | Стёкла/линзы/тач | цвет / тип | `BLK`, `WHT`, `CLR-2.5D` |
| `CBL` | Кабели | интерфейс-интерфейс-длина-цвет | `USBC-LTN-1M-WH` |
| `CHR` | Зарядные устройства | мощность-технология-вилка | `20W-EU`, `65W-GAN-EU` |
| `CAM` | Камеры | позиция-MP | `REAR-12MP`, `FRONT-7MP` |
| `FLX` | Шлейфы | назначение | `CHARGE`, `VOLUME` |
| `IC` | Микросхемы/PMIC | модель/код | `U2`, `TRISTAR` |
| `PRT` | Прочие запчасти | свободно | `BRACKET`, `FRAME-BLK` |
| `SET` | Наборы/комплекты | состав / количество | `KIT-5PCS`, `KIT-SCREWS` |

При необходимости список `CAT` дополняется решением ответственного за каталог.

### 3.1. Уточнение для аккумуляторов (`BAT`)

Для аккумуляторов применяется следующий приоритет:

1. Если известна надёжная номинальная ёмкость, в `KEY` используется именно она: `3470`.
2. Для повышенной ёмкости используется `HCxxxx`: `HC3470`.
3. Если ёмкость отсутствует, не подтверждена, неоднозначна или различается по источникам, допускается использовать код аккумулятора производителя/модуля:
   - `A1527`
   - `EB-BS901ABY`
   - `HB476489EFW`

Это правило введено для снижения доли ручной обработки и для сохранения глобальной уникальности SKU в реальном каталоге.

## 4. Правила уникальности и конфликтов

1. Глобальная уникальность SKU. Один SKU = одна номенклатура.
2. Для мультибренда уникальность обеспечивается префиксом `BR` (`F5-…`, `OFN-…`), что исключает дубли SKU между брендами.
3. `REV` используется только если всё одинаково по `BR/CAT/DEV/KEY`, но нужна отдельная карточка:
   - другой поставщик;
   - другой коммерческий вариант;
   - другая ревизия узла.
4. Запрещено выпускать новый SKU, который полностью совпадает с существующим.

### 4.1. Уточнение по `REV` для аккумуляторов

Для аккумуляторов `REV` допускается использовать для различения коммерчески разных исполнений одного и того же аккумулятора при одинаковых `DEV` и `KEY`.

Типовые случаи:

- `PR` — Premium
- `OR-SP` — ORIG100 / Service Pack
- `HC-NF` — High Capacity без шлейфа
- иные краткие варианты при наличии реальной коммерческой разницы

Принцип:

- если разница только маркетинговая и не создаёт отдельную номенклатуру, `REV` не добавляется;
- если в каталоге это отдельная товарная карточка, `REV` допустим.

## 5. Старые и новые товары

- Старые: существующие числовые Артикулы не меняем.
- Новые: присваиваем по схеме `<BR>-<CAT>-<DEV>-<KEY>-<REV?>`.
- Печатные формы уже используют поле «Артикул», дополнительных доработок не требуется.

## 6. Связь SKU с техидентификацией (для ДС/инвойсов)

- Технический идентификатор (`TradeName`) ведётся во внешнем реестре и используется в ДС/инвойсах/PL наряду со SKU.
- Обязательные поля реестра:
  - `SKU`
  - `TradeName`
  - `V`
  - `mAh`
  - `Wh`
  - `DIM`
  - `BMS`
  - `Connector`
  - `Совместимость`
  - `ТН ВЭД`
- В инвойс/PL выводим: `SKU + TradeName + параметры (V/mAh/Wh) + ТН ВЭД`.

## 7. Процесс присвоения SKU (операционный)

1. Определить `BR`, `CAT`, `DEV`.
2. Определить `KEY` по правилам категории.
3. При необходимости добавить `REV`.
4. Проверить уникальность по 1С.
5. Записать SKU в карточку номенклатуры (поле «Артикул»).
6. Внести строку в реестр `SKU ↔ TradeName ↔ параметры`.
7. Привязать штрихкод / GTIN к SKU.

### 7.1. Порядок автоматической обработки

Автоматический контур выполняется строго в порядке:

1. импорт карточки из 1С;
2. нормализация и сохранение `subject_generated` и связанных вычисленных свойств;
3. пересчёт эффективной классификации товара;
4. генерация SKU;
5. отправка `Предмета` и SKU в 1С.

Классификация, использованная только при формировании XML и не сохранённая
в БД `pricing-service`, не считается завершённым обогащением и не должна быть
основанием для запуска генератора SKU.

## 8. Требования к качеству записи

- Только латиница/цифры и дефис.
- Запрещены пробелы, кириллица и спецсимволы: `/ \\ _ . , * ! ? : ;`.
- Не использовать двусмысленные `DEV`; придерживаться согласованных шаблонов (`IPH`, `SMG`, `XMI`, `HWE` и т.д.).
- `KEY` писать кратко и строго по категории.
- Максимальная длина — 35 символов.

## 9. Изменение SKU

- SKU стабилен.
- Изменение допускается только при критической ошибке:
  - ошибка бренда,
  - ошибка категории,
  - ошибка платформы,
  - неверный ключевой параметр.

При изменении:

1. согласование с ответственным за каталог;
2. актуализация всех привязок;
3. обновление строки в реестре;
4. уведомление заинтересованных команд.

## 10. Ответственность и роли

- Владелец правил: руководитель каталога / закупок.
- Присвоение SKU: менеджер каталога / закупок.
- Контроль коллизий: ответственный за 1С / каталог.
- Внешний реестр `SKU ↔ TradeName`: комплаенс / сертификация.

## 12. FAQ

**Можно ли оставить старые числовые Артикулы?**  
Да. Для новых товаров используется шаблонная схема.

**TradeName обязателен в 1С?**  
Нет. Он ведётся во внешнем реестре.

**Что если один тип товара продаётся под разными брендами?**  
Используйте разные `BR`.

**Что если нужен второй SKU для почти одинаковой позиции?**  
Добавьте `REV`, если это действительно отдельная номенклатура.

**Можно ли для аккумулятора использовать код батареи вместо mAh?**  
Да, если номинальная ёмкость отсутствует, не подтверждена или неоднозначна.
